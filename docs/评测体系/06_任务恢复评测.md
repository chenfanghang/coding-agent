# 任务恢复评测

> 任务恢复不是重新加载聊天记录，而是在进程或会话中断后，恢复结构化目标与待办，并根据当前 Workspace 重新验证旧证据是否仍然可信。

---

## 1. 被测机制如何实现

Pico 将任务目标、下一步、Todo、运行身份和证据摘要写入 Checkpoint。恢复时先比较运行身份与文件新鲜度，再决定完整恢复、部分恢复或重建状态。

```text
原任务执行
   |
   v
Checkpoint：Goal / Next Step / Todo / Evidence / Runtime Identity
   |
   v
新会话加载 Checkpoint
   |
   +---- Workspace 一致 ----> 恢复任务并继续
   |
   +---- 文件已变化 --------> 标记陈旧，重新读取锚定
   |
   +---- Workspace 不一致 --> 拒绝旧运行身份，重建状态
```

主要实现与入口：

- [`pico/core/runtime_checkpoints.py`](../../pico/core/runtime_checkpoints.py)：Checkpoint 数据与恢复。
- [`pico/core/workspace.py`](../../pico/core/workspace.py)：Workspace 身份与边界。
- [`pico/evaluation/metrics.py`](../../pico/evaluation/metrics.py)：Recovery Ablation。
- [`tests/test_metrics.py`](../../tests/test_metrics.py)：产物和聚合合同。

---

## 2. 要验证的问题

- 中断后是否恢复原目标和未完成 Todo？
- 恢复后的首个动作是否与任务下一步一致？
- 文件内容变化后是否识别旧摘要已经陈旧？
- Workspace 身份变化后是否拒绝直接续跑？
- 无效 Checkpoint 是否会被错误接受？
- 恢复机制关闭时，上述能力是否明显退化？

---

## 3. 对照实验设计

相同恢复任务分别运行：

| 变体 | 行为 |
|---|---|
| `resume_enabled` | 加载 Checkpoint，并执行新鲜度与 Workspace 校验 |
| `resume_disabled` | 不加载结构化恢复状态 |

当前 Recovery Ablation 包含 11 个任务，覆盖有效恢复、陈旧证据、Workspace Drift、无效状态拒绝和跨会话连续性。

---

## 4. 指标含义

| 指标 | 评测含义 |
|---|---|
| Resume 成功率 | 有效 Checkpoint 是否恢复出可继续执行的正确状态 |
| 陈旧状态重新锚定率 | 旧证据失效时是否重新读取真实环境 |
| Workspace Drift 识别率 | 运行身份变化是否被发现 |
| 错误接受率 | 无效或不安全状态是否被错误采用 |
| 跨会话续接成功率 | 新会话是否继续完成原任务 |
| 首个恢复动作正确率 | 恢复后的第一步是否符合预期 |
| Todo 连续率 | 未完成事项是否跨会话保留 |

恢复成功率与跨会话续接成功率不是同一指标：前者验证状态能否恢复，后者验证恢复后能否完成后续行为。

---

## 5. 当前结果

| 指标 | 开启恢复 | 关闭恢复 |
|---|---:|---:|
| Resume 成功率 | 90% | 0% |
| 陈旧状态重新锚定率 | 100% | 0% |
| Workspace Drift 识别率 | 100% | 0% |
| 错误接受率 | 0% | 0% |
| 跨会话续接成功率 | 100% | 0% |
| 首个恢复动作正确率 | 100% | 0% |
| Todo 连续率 | 100% | 0% |

`错误接受率` 两组均为 0%，不能单独用于证明 Resume 的收益；它说明当前无效状态案例没有被任何变体错误接受。Resume 的主要收益体现在有效状态恢复、重锚定、漂移识别和连续执行。

---

## 6. Verifier 证据

任务恢复不能只检查最终文本，至少需要组合：

- `report.json` 中的 `resume_status`。
- `trace.jsonl` 中的 Checkpoint、Freshness Mismatch 和 Runtime Identity 事件。
- 恢复后第一个工具调用。
- Todo 状态是否连续。
- Workspace 最终文件是否符合任务要求。

---

## 7. 面试表达

> “Pico 的 Resume 不是把聊天历史塞回 Prompt，而是恢复 Goal、Next Step、Todo、Evidence 和 Runtime Identity。恢复前会比较文件新鲜度和 Workspace 身份；如果旧摘要对应的文件已经变化，就降级为部分恢复并强制重新读取，如果工作区不一致则拒绝直接续跑。评测上我用开启和关闭 Resume 的消融组，分别检查恢复成功、重锚定、Drift、首个动作和 Todo 连续性。目前恢复成功率 90%，漂移识别和陈旧状态重锚定均为 100%。”
