# Pico 评测体系：全景与阅读导航

> 本模块解释 Pico 当前的评测是**如何设计、如何执行、如何判定和如何复现**的。它不把模型回答得像不像作为唯一标准，而是同时检查 Agent 的执行轨迹、工具行为、工作区最终状态和资源消耗。

---

## 1. 为什么 Coding Agent 需要独立评测体系

Pico 是面向本地代码仓库任务的 Agent Harness。一次任务通常包含多轮模型调用、文件读取、代码修改、测试执行、上下文压缩、记忆召回和任务恢复。因此，HumanEval 一类单轮代码生成指标无法回答以下问题：

- 模型调用工具失败后，Agent 能否恢复并完成任务？
- Agent 是否真的修改了正确文件，而不是只输出一段看似合理的文本？
- 上下文压缩后，当前请求和安全约束是否仍然存在？
- 跨会话记忆是否召回了正确事实，是否过滤了陈旧或敏感内容？
- Workspace 已经变化时，恢复逻辑会重新锚定还是错误续跑？
- 真实模型的随机性是否掩盖了 Harness 本身的工程回归？

Pico 因而采用分层评测：先验证确定性规则，再验证模块收益，最后使用真实模型和完整任务做端到端验收。

```text
+-----------------------------+
| L1  静态质量与单元规则测试   |
| 语法、风格、函数与边界行为   |
+--------------+--------------+
               |
               v
+-----------------------------+
| L2  Harness 确定性回归       |
| 固定任务、固定响应、真实运行时|
+--------------+--------------+
               |
               v
+-----------------------------+
| L3  模块消融与专项挑战       |
| Context / Memory / Recovery  |
+--------------+--------------+
               |
               v
+-----------------------------+
| L4  Live Provider 与真人场景 |
| DeepSeek + 真实完整执行链路  |
+-----------------------------+
```

## 2. 当前评测版图

| 评测层 | 核心问题 | 是否调用真实模型 | 主要判定证据 |
|---|---|---:|---|
| 静态质量与单元测试 | 单个规则和边界是否正确 | 否 | Pytest、Ruff |
| Harness Regression | 控制循环和工具合同是否稳定 | 否 | 文件状态、`report.json`、`trace.jsonl` |
| 上下文评测 | 是否在保留任务信息的同时减少上下文压力 | 部分 | Prompt、Token、正确率、Verifier |
| 记忆评测 | 能否跨会话召回、更新并安全使用事实 | 部分 | Answer、Evidence、工具轨迹、存储状态 |
| 任务恢复评测 | 中断后能否依据当前环境安全续接 | 否 | Resume 状态、首个动作、漂移事件 |
| 安全治理评测 | 危险行为和不可信数据是否被阻断 | 部分 | 安全事件、工具结果、最终落盘状态 |
| 真人场景验收 | 完整产品链路在真实任务中是否可用 | 是 | 场景检查项、Workspace、Trace、Provider 响应 |

## 3. 推荐阅读顺序

1. [评测目标与分层方法](./01_评测目标与分层方法.md)：先理解每一层解决什么问题。
2. [统一实验协议与指标口径](./02_统一实验协议与指标口径.md)：掌握对照实验、Verifier 和指标定义。
3. [Agent Harness 确定性回归评测](./03_Agent_Harness确定性回归评测.md)：理解固定 Benchmark 如何隔离模型随机性。
4. [上下文编排与成本评测](./04_上下文编排与成本评测.md)：理解稳定前缀、压力感知压缩和 LLM Handoff（详解参见 [docs/上下文/README.md](../上下文/README.md)）。
5. [跨会话记忆评测](./05_跨会话记忆评测.md)：理解记忆消融、挑战集和真实模型矩阵（详解参见 [docs/记忆/README.md](../记忆/README.md)）。
6. [任务恢复评测](./06_任务恢复评测.md)：理解 Checkpoint、重锚定与 Workspace Drift。
7. [运行时安全与记忆治理评测](./07_运行时安全与记忆治理评测.md)：理解工具安全和记忆安全的不同验收方式（详解参见 [docs/工具调用/README.md](../工具调用/README.md)）。
8. [真实模型与真人场景验收](./08_真实模型与真人场景验收.md)：理解 Human50、Gate8 和业务 Dogfood。
9. [评测产物复现与结果解读](./09_评测产物复现与结果解读.md)：从任务定义追溯到最终报告。
10. [当前结论、局限与后续增强](./10_当前结论局限与后续增强.md)：明确数据能证明什么、还不能证明什么。

## 4. 文档与数据的职责边界

| 位置 | 职责 |
|---|---|
| `docs/评测体系/` | 评测方法、实验设计、指标口径和复现方式 |
| `docs/metrics/` | 某次运行的结果快照和面向用户的数据报告 |
| `benchmarks/` | 固定任务与长会话任务定义 |
| `pico/evaluation/` | 评测执行、聚合和报告生成实现 |
| `scripts/` | Live、Gate、Dogfood 等运行入口 |
| `artifacts/` 或独立报告目录 | 原始 Workspace、Trace、JSON 和报告产物 |

> **事实来源原则**：代码定义评测行为，机器可读产物保存运行事实，Markdown 报告负责解释；简历和面试表述只能引用前述证据。
