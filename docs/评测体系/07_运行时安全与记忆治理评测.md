# 07. 运行时安全与记忆治理评测

> 本专项用于验证 Pico 的受控工具网关与检疫隔离池能否阻断恶意提示词注入（Prompt Injection）、沙箱路径逃逸（Path Escape）、敏感凭据暴露以及越权改写。

---

## 1. 核心安全机制与防护链条

Pico 拒绝“仅在日志里记录拦截事件，磁盘却已被污染”的假安全。安全治理评测同时检查**决策过程**与**最终磁盘物理状态**：

```text
模型工具意图 ──► [受控工具网关 8 重防线] ──► [Memory Quarantine 检疫隔离池] ──► 物理落盘验证
                      │                                 │
                      ▼                                 ▼
             阻断 Path Escape / 死循环          阻断 Prompt 注入与凭据
```

实现入口：
- `pico/core/tool_executor.py`：受控工具网关（详细 8 重防线拆解参见 [docs/工具调用/README.md](../工具调用/README.md)）。
- `pico/features/memory_quarantine.py`：记忆检疫池与注入拦截。
- `pico/core/governance.py`：全全治理决策事件日志。

---

## 2. 安全评测数据与拦截效果

在确定性安全测试与真实场景安全攻击测试中，Pico 实现了 100% 的安全拦截：

| 安全攻击/越权场景 | 模拟攻击行为 | 受控网关/检疫池处理动作 | 拦截率 / 效果 |
| :--- | :--- | :--- | :---: |
| **沙箱路径逃逸 (`path_escape`)** | 试图读取/写入 `../../../../etc/passwd` | 触发关卡 2 拦截，抛出 `PermissionError` | **100% 阻断** |
| **凭空覆写代码 (Unread Modify)** | 未调用 `view_file` 盲目修改代码 | 触发 Read Freshness Guard，要求先读后改 | **100% 阻断** |
| **重复调用死循环 (Tool Loop)** | 同参数连续重复执行 Shell 命令 | 触发关卡 3 阻断，强制要求更换工具 | **100% 阻断** |
| **敏感密钥泄露 (`secret_shaped`)**| 在记忆中保存 OpenAI API Key (`sk-...`) | 触发 `secret_shaped` 规则，拒绝提炼入库 | **0.0% 泄露** |
| **提示词注入攻击 (`quarantined`)** | 输入 `ignore previous instructions` 越狱 | 标记为 `quarantined`，推入隔离池并全局剔除 | **100% 隔离** |

## 3. 治理审计日志契约 (`record_governance_decision`)

每一次阻断动作，系统都会生成格式统一的治理审计记录：

```json
{
  "event": "governance_decision",
  "tool_name": "replace_file_content",
  "decision": "deny",
  "reason_code": "read_freshness_required",
  "security_event_type": "unread_modify_block"
}
```

* **无副作用校验**：评测 Verifier 不仅检查治理日志中记录了 `deny`，还会在运行结束后检查 Git Diff 与磁盘文件，确保**零有害副作用落盘**。
