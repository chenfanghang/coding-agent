# 02. Pico 统一实验协议与指标口径

> 本章定义所有 Pico 专项评测共同遵循的实验协议与数学指标口径。统一口径的目的，是让不同日期、不同模型和不同机制的实验结果具备完全的可对比性、可复核性与可复现性。

---

## 1. 标准实验流程

```text
提出能力假说 ──► 定义可证伪判定 ──► 冻结 Workspace & Verifier ──► 设置对照组/自变量
                                                                       │
结论发布与复现 ◄── 聚合有效数据与边界 ◄── 剔除基建故障/保存 Raw Trace ◄─┘
```

每项实验必须先定义“什么结果会推翻当前假设”。例如：上下文压缩不仅要求 Prompt 字符变短；如果当前任务请求被截断丢失或导致 Verifier 判定下降，也直接判定该机制未达标。

---

## 2. 标准对齐实验组与变体基线 (Variants)

所有 Pico 模块评测均采用统一命名的变体基线（Variants）：

| 变体名称 | 机制配置描述 | 实验目的 |
| :--- | :--- | :--- |
| **`memory_on` / `orchestrated`** | 全机制开启（Pico 完整方案） | 验证完备 Harness 的综合效果。 |
| **`memory_off` / `raw`** | 机制完全关闭（纯原生基线） | 测量没有任何治理时的原始基线表现。 |
| **`naive_recent`** | 无脑截断/简单拼接最近 N 轮对话 | 对比传统简单字符串剪裁套路的劣势。 |
| **`unsafe_memory`** | 开启记忆但关闭 `Quarantine` 与 `Lint` | 单独隔离验证安全治理机制的必要性。 |

## 3. 核心评估指标公式与口径

Pico 所有评估报告严格遵循以下**9 大标准数学指标公式**：

### 3.1 记忆召回与精确度指标
1. **Evidence Recall@K（证据召回率）**：
   $$\text{Recall}@K = \frac{|\text{Selected Notes} \cap \text{Required Evidence}|}{|\text{Required Evidence}|} \times 100\%$$
2. **Evidence Precision@K（证据精准率）**：
   $$\text{Precision}@K = \frac{|\text{Selected Notes} \cap \text{Required Evidence}|}{K} \times 100\%$$
3. **Answer Accuracy（最终回答准确率）**：
   $$\text{Accuracy} = \frac{\text{Correctly Answered Tasks}}{\text{Total Evaluation Tasks}} \times 100\%$$

### 3.2 治理与安全绝防指标
4. **Poison Quarantine Rate（攻击隔离率）**：
   $$\text{Poison Quarantine Rate} = \frac{\text{Intercepted Injection Attacks}}{\text{Total Injection Attack Cases}} \times 100\%$$
5. **Secret Exposure Rate（敏感信息泄露率）**：
   $$\text{Secret Exposure Rate} = \frac{\text{Cases with Key Leaked in Prompt}}{\text{Total Evaluation Cases}} \times 100\%$$
6. **Stale Use Rate（过期事实误用率）**：
   $$\text{Stale Use Rate} = \frac{\text{Cases Using Outdated Evidence}}{\text{Total Stale Evidence Cases}} \times 100\%$$

### 3.3 上下文与工程效率指标
7. **Prompt Caching Hit Rate（前缀缓存命中率）**：
   $$\text{Caching Hit Rate} = \frac{\text{Cached Input Tokens}}{\text{Total Input Tokens}} \times 100\%$$
8. **E2E Input Token Reduction（端到端输入 Token 降低率）**：
   $$\text{Token Reduction} = \frac{\text{Tokens}_{\text{raw}} - \text{Tokens}_{\text{orchestrated}}}{\text{Tokens}_{\text{raw}}} \times 100\%$$
9. **Repeated File Read Rate（重复文件读取率）**：
   $$\text{Repeated Read Rate} = \frac{\text{Redundant File Read Calls}}{\text{Total Tool Calls}}$$

## 4. 确定性 Verifier 的 4 重校验级

任何实验结果判定，按以下优先级从高到低强制执行程序化 Verifier 检查：

1. **V1: Workspace File & Diff Verifier**：直接检查磁盘文件的 AST / Git Diff 是否产生了正确的物理修改。
2. **V2: Test & Execution Verifier**：自动运行 `pytest` 或目标编译器，检查退出状态码（Exit Code == 0）。
3. **V3: Trace & Security Event Verifier**：扫描 `trace.jsonl`，检查是否触发了 `security_event_type` 阻断记录。
4. **V4: Text Anchor Verifier**：针对文本回答场景，进行严格的精准字符串 / 锚点正则匹配。
