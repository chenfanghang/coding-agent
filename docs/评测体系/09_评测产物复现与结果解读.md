# 评测产物复现与结果解读

> 本章说明如何从任务定义运行到机器可读产物，再从原始证据生成面向用户的报告。命令以项目当前 `uv` 环境为准；Live 运行需要有效的 Provider 配置和独立输出目录。

---

## 1. 证据链

```text
任务定义 / Fixture
        |
        v
隔离 Workspace + 运行配置
        |
        v
.pico/runs/<run_id>/
  |- trace.jsonl
  |- report.json
  `- artifacts/
        |
        v
专项 JSON / CSV / Summary
        |
        v
自动 Markdown 报告
        |
        v
简历指标与面试表达
```

越靠近上游，证据越原始；越靠近下游，解释越方便但越可能遗漏口径。出现冲突时，应回到原始产物和评测代码核对。

---

## 2. 关键产物

| 产物 | 作用 |
|---|---|
| `trace.jsonl` | 逐事件记录模型、工具、门禁、压缩和恢复轨迹 |
| `report.json` | 单次 Run 的状态、使用量和汇总元数据 |
| Workspace 副本 | 验证最终文件、测试和副作用 |
| 专项 JSON | 保存各任务、变体、重复和聚合指标 |
| `SUMMARY.json` | 汇总一次完整评测的主要结果与路径 |
| Markdown Report | 面向阅读者解释结果，不作为唯一真值 |

当前完整报告索引见：[Pico 评测结果数据报告](../metrics/Pico评测结果数据报告-DeepSeek-V4-Flash-20260729.md)。

## 4. Harness Regression

当前执行函数尚未提供独立 CLI，可通过公开 Python 入口运行：

```bash
uv run python -c \
  "from pico.evaluation.evaluator import run_harness_regression_v2; run_harness_regression_v2()"
```

默认产物为 `artifacts/harness-regression-v2.json`。验证实现合同：

```bash
uv run pytest tests/test_evaluator.py tests/test_benchmark_integrations.py
```

## 6. 上下文与 LLM Handoff

确定性 Prompt 实验：

```bash
uv run python scripts/run_context_cost_experiment.py \
  --mode deterministic \
  --output-dir artifacts/context-cost-deterministic \
  --repetitions 5
```

LLM Handoff 脚本化配对实验：

```bash
uv run python scripts/run_llm_handoff_benchmark.py \
  --mode scripted \
  --output-dir artifacts/llm-handoff-scripted \
  --repetitions 3
```

真实 DeepSeek 配对实验：

```bash
uv run python scripts/run_llm_handoff_benchmark.py \
  --mode live \
  --provider deepseek \
  --output-dir artifacts/llm-handoff-live \
  --repetitions 3
```

Live 运行前必须确认 Provider Profile 指向 `deepseek-v4-flash`，并在产物中复核实际模型名称。

## 7. 真人场景与业务 Dogfood

Human50 输出目录必须在仓库外：

```bash
uv run python scripts/run_v3_human_scenario_gate.py \
  --suite full \
  --provider deepseek \
  --output-dir /tmp/pico-human50
```

单独重跑 S45：

```bash
uv run python scripts/run_v3_human_scenario_gate.py \
  --suite full \
  --provider deepseek \
  --scenario S45 \
  --output-dir /tmp/pico-human-s45
```

Gate8 与 Live Smoke：

```bash
uv run python scripts/run_real_session_acceptance.py \
  --output-dir artifacts/gate8-real-session-acceptance \
  --live-provider
```

业务 Dogfood：

```bash
uv run python scripts/run_business_scenario_dogfood.py \
  --provider deepseek \
  --model deepseek-v4-flash \
  --output-dir /tmp/pico-business-dogfood
```

## 8. 如何确认没有误用其他模型

1. 检查启动参数和配置中的 Provider Profile。
2. 搜索正式 Live 产物中的模型名称。
3. 确认 `deepseek-v4-flash` 命中，且 `deepseek-v4-pro` 为 0。

2026-07-29 报告记录正式 Live 文件中 `deepseek-v4-flash` 命中 61 个文件、`deepseek-v4-pro` 命中 0 个文件。

## 9. 结果审计清单

- [ ] Task Set、Git Commit 和模型身份可定位。
- [ ] 对照组和实验组只改变目标机制。
- [ ] 重复次数和有效样本数已记录。
- [ ] 成功由 Verifier 和最终状态决定，不依赖模型自述。
- [ ] Provider、环境和 Verifier 失败已单独分类。
- [ ] 字符、Token、缓存和价格指标没有混用。
- [ ] 聚合指标可以从机器可读产物重新计算。
- [ ] 失败案例和负向结果没有被删除。
- [ ] 结论明确限定模型、任务集和运行日期。
