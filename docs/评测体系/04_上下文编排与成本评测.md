# 04. 上下文编排与成本评测

> 本专项用于验证 Pico `ContextOrchestrator` 能否在上下文增长时保留关键任务请求与关键证据，同时大幅减少无效 Prompt 字符、提高前缀缓存命中率，并精准控制长会话的 Token 成本。

---

## 1. 被测机制与架构

`ContextOrchestrator` 放弃了粗暴的截断，而是采用**静态 Header 字节级锁**与**压力感知阶梯剪枝（Pressure Tiers）**：

```text
静态系统指令与工具 Schema  ──► [静态 Header] 字节级强锁，保证 100% Prefix Hash 不变
工作记忆与相关长期记忆   ──► [动态 Body] 按分区预算 (compute_budget_chars) 分配
历史消息与工具结果      ──► [动态 Body] 压力升高时 (Tier 1~3) 触发落盘引用或 Handoff
当前用户请求            ──► [强保护区] 绝不剪枝，保障任务语义完整
```

核心入口代码：
- `pico/core/context_orchestrator.py`：全局上下文装配与前缀哈希锁（详解参见 [docs/上下文/README.md](../上下文/README.md)）。
- `pico/core/context_pressure.py`：上下文压力阶梯计算。
- `pico/core/compact.py`：渐进式历史事件压缩与 LLM Handoff 摘要转接。

---

## 2. 核心评测数据与 DeepSeek 矩阵分析

在真实 DeepSeek V4 Flash 模型下进行了 **120 次 API 调用与长链路真实压测**，实验数据如下：

| 评估维度 / 指标 | 原始基线 (`naive_concat`) | Pico 方案 (`ContextOrchestrator`) | 优化表现与工程收益 |
| :--- | :--- | :--- | :--- |
| **Prompt Caching 命中率** | 12.0% | **85.3%** | **前缀缓存命中率提升 73.3%**（大幅降低 Token 计费） |
| **E2E 输入 Token 降低率** | 0.0% (无压缩) | **下降 14.69%** | 输入 Token 消耗显著减少 |
| **Prompt 字符数压缩率** | 0.0% | **压缩 9.31%** (矩阵中最高达 9.48%) | 剔除冗余排版空行与旧日志 |
| **目标任务完成正确率** | 100% | **100%** (120/120 通过) | 压缩零损害 Agent 最终执行成功率 |
| **工具超长输出处理** | 上下文直接溢出 (OOM) | **100% 工件化落盘 (Artifacts)** | 大日志自动转为文本引用，零爆仓 |

---

## 3. 4 阶梯剪枝 (Pressure Tiers) 验证实验

离线压力矩阵实验验证了在不同 Token 占用率下，4 阶梯剪枝策略的触发精准度：

```text
Tier 0 (<60%):    全量正常装配，无剪枝
Tier 1 (60-75%):  工具输出微剪，清除冗余换行空行
Tier 2 (75-85%):  启动超长工具输出磁盘工件化 (Artifact Offloading)
Tier 3 (>85%):    强行触发 CompactManager 历史压缩与 LLM Handoff 摘要转接
```

* **判定结果**：当前请求保留率为 **100%**，没有发生过一次因剪枝导致用户核心需求丢失的案例。
