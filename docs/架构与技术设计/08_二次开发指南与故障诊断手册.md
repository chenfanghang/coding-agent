## 8.1 自定义工具 (Custom Tool) 开发 SOP

在 Pico v3 中，所有工具均在 [pico/tools/registry.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/tools/registry.py) 中注册。编写一个新工具需要遵从 4 步标准范式：

```python
# Step 1: 在 pico/tools/schemas.py 定义 Pydantic v2 参数校验结构
from pydantic import BaseModel, Field

class FormatJsonArgs(BaseModel):
    file_path: str = Field(..., description="目标 JSON 文件物理路径")
    indent: int = Field(default=2, ge=1, le=8, description="缩进空格数")

# Step 2: 在 pico/tools/registry.py 编写物理 Runner 函数
def tool_format_json(args: dict, workspace_root: Path) -> ToolResult:
    path = workspace_root / args["file_path"]
    data = json.loads(path.read_text(encoding="utf-8"))
    formatted = json.dumps(data, indent=args.get("indent", 2), ensure_ascii=False)
    path.write_text(formatted, encoding="utf-8")
    return ToolResult(content=f"已成功格式化 {args['file_path']}")

# Step 3: 注册至 _TOOL_SCHEMAS 与 BASE_TOOL_SPECS
_TOOL_SCHEMAS["format_json"] = FormatJsonArgs
BASE_TOOL_SPECS["format_json"] = {
    "schema": {"file_path": "str", "indent": "int=2"},
    "risky": True,  # 修改物理文件标记为有副作用
    "description": "Format a local JSON file.",
}

# Step 4: 在 pico/core/tool_profiles.py 绑定暴露面 Profile
DEFAULT_PROFILE_TOOLS.append("format_json")
```

## 8.2 自定义 Model Provider 集成指南

在 [pico/providers/clients.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/providers/clients.py) 中，只需实现包含 `complete(prompt, max_new_tokens)` 的 Client 类，即可接入本地 Ollama / vLLM 或私有 LLM 服务：

```python
class CustomOllamaClient:
    def __init__(self, base_url="http://localhost:11434", model="qwen2.5-coder"):
        self.base_url = base_url
        self.model = model

    def complete(self, prompt: str, max_new_tokens: int = 4096, **kwargs) -> str:
        resp = requests.post(f"{self.base_url}/api/generate", json={
            "model": self.model, "prompt": prompt, "stream": False
        })
        return resp.json().get("response", "")
```

随后在 [pico/providers/runtime.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/providers/runtime.py) 的 `create_model_client()` 工厂中注册 key 即可完成动态加载。

## 8.3 高频故障诊断与 Troubleshooting 排查 SOP

### 1. 前缀缓存 (Prompt Caching) 频繁 Cache Miss
- **现象**：大模型 API 计费陡增，前缀缓存命中率由 85% 掉至 < 15%，系统首包响应非常缓慢。
- **排查 SOP**：
  1. 打开 `.pico/runs/<run_id>/trace.jsonl`，查看连续两轮 `prompt_built` 事件的 `prefix_hash`；
  2. 若 `prefix_hash` 发生改变，检查是否在 `System Header` 中误注入了动态系统时间或随机 ID；
  3. 确保所有动态变量严格存放在 `Tail Body` 区域。

### 2. `FinalReadiness` 连续打回与测试失败
- **现象**：修改代码后模型反复被打回，系统提示 `Final answer blocked by runtime readiness gate`。
- **排查 SOP**：
  1. 检查物理环境测试是否正常：运行 `pytest` 查看是否有环境破坏；
  2. 若是环境报错，连续阻断 3 次后系统会自动触发降级放行或唤醒 TUI HITL 人工确认。

### 3. Context 90% 物理红线与溢出保护
- **现象**：终端触发 `tier3_summary` 警告。
- **排查 SOP**：系统会自动激活 `compact_history()`，冻结 Header 并提纯中间历史。亦可通过输入 `/compact` 命令手动触发压缩，释放 70%+ Token 预算。

### 4. Auto-Dream PID 锁死 (`.consolidate-lock`)
- **现象**：后台守护进程提示 `consolidation locked` 警告。
- **排查 SOP**：检查持锁进程 PID 存活性，系统会在 300 秒超时 (`HOLDER_STALE_S = 300`) 后强行拆锁释放死锁，亦可运行 `/dream --force` 手动解锁。
