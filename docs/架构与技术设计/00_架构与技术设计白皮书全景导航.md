# Pico v3 架构与技术设计白皮书

> **文档定位**：面向希望理解、维护或面试讲解 Pico 的开发者，系统说明它为什么这样设计、请求如何运行、状态如何治理，以及结论如何追溯到源码与评测。

---

## 1. Pico 是什么

Pico 是运行在本地代码仓库中的 **Coding Agent Harness**。大模型负责理解任务、选择下一步动作；Harness 负责管理上下文、工具权限、任务状态、恢复条件、完成门禁和审计证据。

```text
                         +----------------------+
用户任务 ---------------->|  Pico Agent Runtime  |
                         +----------+-----------+
                                    |
             +----------------------+----------------------+
             |                      |                      |
             v                      v                      v
      Context & Memory       Tool & Governance      State & Recovery
      上下文与跨会话记忆       工具执行与安全治理        任务状态与恢复
             |                      |                      |
             +----------------------+----------------------+
                                    |
                                    v
                         Trace / Report / Artifacts
```

它的重点不是“让模型多调用几个工具”，而是把开放式模型决策放入一条可控制、可恢复、可审计、可评测的执行链路。

## 2. 架构能力地图

| 能力域 | 解决的问题 | 核心机制 | 主要源码 |
| :--- | :--- | :--- | :--- |
| **Agent Runtime** | 多轮任务如何持续推进 | Engine 循环、TaskState、步骤预算、停止原因 | `pico/core/runtime.py`、`engine.py` |
| **上下文工程** | 长会话如何控制输入规模 | 稳定前缀、压力分级、历史压缩、长结果落盘 | `context_orchestrator.py`、`context_pressure.py` |
| **跨会话记忆** | 新会话如何复用项目事实 | 分层文件记忆、相关性排序、新鲜度、检疫 | `pico/features/memory.py` |
| **工具治理** | 如何约束模型副作用 | Schema、Permission、Policy、快照 Diff | `tool_executor.py`、`permissions.py` |
| **任务恢复** | 中断后如何安全续接 | Checkpoint、文件新鲜度、Runtime Identity、Drift | `runtime_checkpoints.py`、`workspace.py` |
| **规划与协同** | 复杂任务如何拆分和隔离 | Plan Mode、TodoLedger、Worker、`write_scope` | `plan_mode.py`、`todo_ledger.py`、`worker_manager.py` |
| **完成治理** | 如何避免无证据交付 | Final Readiness 原因集合与分级决策 | `final_readiness.py` |
| **审计与评测** | 如何定位失败并证明效果 | TaskState、Trace、Report、Scripted/Live Eval | `run_store.py`、`pico/evaluation/` |

## 4. 如何用这套白皮书准备面试

每章末尾都提供一组轻量的“面试表达”，包含：

1. **30 秒讲法**：先给结论，再说明核心实现；
2. **项目推演题**：根据当前项目与简历表述推导，不冒充真实面经；
3. **回答边界**：指出不能过度宣称的能力或指标；
4. **延伸练习**：跳转到完整题库和可直接口述的参考答案。

推荐练习顺序是“先读实现 → 脱稿讲 30 秒 → 连续回答追问 → 回到源码或报告校验口径”。架构正文用于建立理解，章节末尾用于快速复述，完整面试文档用于训练长答案与追问链路。

## 5. 文档事实口径

> [!IMPORTANT]
> 架构文档负责解释“系统如何工作”；评测文档负责解释“效果如何证明”。二者互相引用，但不能用设计意图替代运行结果。

| 表述类型 | 可接受证据 | 示例 |
| :--- | :--- | :--- |
| **实现事实** | 当前源码中的类、函数、配置或测试 | `tier3_summary` 阈值为 0.95 |
| **评测结果** | 可复算 JSON、Trace、报告和实验协议 | Live Prompt 平均压缩 9.48% |
| **设计目标** | ADR 中的动机与取舍 | 提高稳定前缀的可复用性 |
| **已知限制** | 失败样本或未采集字段 | 当前未采集流式 TTFT |

特别注意：

- 字符缩减率、Token 变化、缓存命中率和账单成本是四种不同指标；
- Provider 返回的 `cached_tokens` 才能支持缓存 Token 分析；
- `model_parsed.duration_ms` 是完整响应与解析耗时，不是 TTFT；
- 场景集通过率只代表当前场景覆盖，不代表生产 SLA。

## 6. 核心术语表

| 术语 | 含义 | 不要混淆为 |
| :--- | :--- | :--- |
| **Session** | 跨多轮交互保存的会话容器 | 单次请求的运行报告 |
| **Turn** | 用户发起的一轮请求及其完整处理过程 | 单次模型调用 |
| **Run** | 一个 Turn 对应的审计与工件目录 | 跨会话长期状态 |
| **TaskState** | 单次任务的目标、步骤、证据和停止状态 | 完整聊天历史 |
| **Checkpoint** | 用于安全续接未完成任务的状态快照 | 长期项目记忆 |
| **Memory** | 可跨会话复用的项目事实与用户偏好 | 正在执行的临时任务状态 |
| **Freshness** | 文件摘要是否仍对应当前物理内容 | 整个 Runtime 是否完全一致 |
| **Runtime Identity** | Provider、模型、工具签名和 Workspace 等运行身份 | 单个文件 Hash |
| **Tool Profile** | 当前模式向模型暴露的工具集合 | 某次工具调用的授权结论 |
| **Permission** | 当前身份是否允许执行工具 | 参数是否合法或过程策略是否满足 |
| **Policy** | 工具在当前过程中的使用规则 | OS 级 Sandbox |
| **Trace** | 单次 Run 内按时间追加的审计事件 | Session 级 UI 事件流 |
| **Report** | 对 TaskState、Trace 和资源数据的归约结果 | 原始事件本身 |
| **Artifact** | 长工具输出、报告等独立落盘工件 | 已经被删除的上下文 |
| **Compact** | 根据规则压缩历史 | 必然调用 LLM 的摘要 |
| **LLM Handoff** | 由模型生成结构化任务交接摘要 | 无额外成本的裁剪 |
