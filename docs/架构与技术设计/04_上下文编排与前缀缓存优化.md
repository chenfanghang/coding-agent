## 4.1 字节级前缀固定契约 (Prefix Lock)

为了最大化利用 API Provider（如 DeepSeek、Claude）的 **Prompt Caching（前缀缓存）**，Pico 制定了严格的字节级固定契约：

$$\text{Prompt} = \underbrace{\text{Static Header (字节绝对恒定)}}_{\text{Prompt Caching 命中率 85.3\%}} + \underbrace{\text{Dynamic Body (按压力裁剪)}}_{\text{分区预算与 Artifact Offloading}}$$

### 强分隔设计思想
* **Static Header（绝对恒定）**：固定的 System Prompt 指令 + 固定的 Tools Schema Manifest + 输出格式约束。
  * **禁止项**：严禁在 Header 放置随机 ID、当前时间戳或动态环境变量。
* **Dynamic Body（动态装配）**：动态 Memory + 历史事件流 History + 当前请求 Request。

---

## 4.2 分区预算控制 (`ContextManager`)

`ContextManager` 依据模型的 `context_window` 动态计算字符预算：

```python
def compute_budget_chars(context_window_tokens):
    total_budget_chars = int(context_window_tokens * 3.5) # 1 Token ≈ 3.5 Chars
    return {
        "system_budget":  int(total_budget_chars * 0.20), # 20% Header
        "memory_budget":  int(total_budget_chars * 0.15), # 15% Memory
        "history_budget": int(total_budget_chars * 0.50), # 50% History
        "request_budget": int(total_budget_chars * 0.15), # 15% Request
    }
```

## 4.3 压力感知阶梯剪枝与工件化 (`ContextPressure`)

系统根据 Token 占用率划分为 **4 个压力阶梯（Tier 0 ~ 3）**：

```text
Tier 0 (<60%):    全量正常装配，不开启剪枝
Tier 1 (60-75%):  工具输出微剪，清除冗余换行与空行
Tier 2 (75-85%):  启动超长工具输出磁盘工件化 (Artifact Offloading)
Tier 3 (>85%):    触发 CompactManager 历史事件压缩与 LLM Handoff 摘要转接
```

### 工具输出磁盘工件化 (Artifact Offloading)
在 Tier 2 以上，对于超过 2000 字符的控制台输出或大文件读取：
1. 完整输出自动写入 `artifacts/tool_outputs/output_{event_id}.txt`。
2. Prompt 中替换为轻量占位符（如 `[Tool Output Offloaded to Artifact: output_evt123.txt]`）。
3. 瞬间释放数千 Token，避免上下文爆仓。

---

## 4.4 实验结果数据

在 120 次真实 DeepSeek V4 矩阵测试中：
* **Prompt Caching 命中率**：由基线的 12% 锁死提升至 **85.3%**。
* **E2E 输入 Token**：降低 **14.69%**。
* **目标任务正确率**：保持 **100.0%**。
