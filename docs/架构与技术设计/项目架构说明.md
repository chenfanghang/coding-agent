# Pico v3 项目架构说明

本文说明 `pico v3` 版本的整体架构、核心对象、主执行链路，以及上下文编排、完成治理、记忆检疫、子 Agent 派发与运行工件如何协作。

阅读时抓紧两条核心主线：

- **装配线 (Setup Line)**：CLI 如何把 workspace、session、模型、审批策略和运行限制装配成 [Pico Runtime](file:///Users/chenfanghang/PycharmProjects/pico/pico/core/runtime.py)。
- **执行线 (Execution Line)**：Runtime 创建完成后，一条用户消息如何经过上下文编排、动态压力控制、ReAct Step 引擎、完成就绪门禁、工具/沙箱与持久化系统。

## 1. 项目定位与工程目标

`pico v3` 是运行在本地代码仓库里的轻量 coding agent。它不是纯聊天程序，而是一个带有工作区感知、受控工具调用、完成治理门禁、分层记忆检疫、子 Agent 派发和运行审计工件的命令行助手。

从工程角度看，`pico v3` 是一个 **local coding agent harness**：它把模型、上下文编排、工具、安全边界、完成治理 (Final Readiness)、记忆隔离池 (Quarantine)、子 Agent (Worker) 和 benchmark 装进一套可执行、可复盘、可评测的框架里。

核心目标：

- 在当前 workspace 内读取文件、修改文件、运行命令。
- 通过稳定 prompt prefix 给模型提供仓库导航信息，并最大化利用 Prompt Caching（前缀缓存）。
- 通过 **Context Orchestrator** 动态调控上下文压力，按需留存与自适应压缩。
- 通过 **Final Readiness** 完成治理门禁，防止模型在任务未真正跑通前**提早盲目退出 (Premature Exit)**。
- 支持 **Memory Quarantine (记忆检疫池)** 防止坏记忆与幻觉污染长期数据库。
- 支持子 Agent (Worker) 并发派发与写范围 (`write_scope`) 沙箱隔离。
- 支持多模态 (Vision / Media) 文本与图像混合上下文解析。

## 3. Pico v3 全路径调用链 (Complete Call Chain)

当用户在 Pico v3 中输入一条指令时，系统内部执行的全路径函数调用树如下：

```text
[用户执行 pico "任务"]
  │
  ├── 1. CLI 启动与 v3 Runtime 装配
  │    └── pico/cli.py -> pico/core/runtime.py: Pico.create()
  │
  ├── 2. 上下文编排与动态压力控制 (v3 Context Orchestrator)
  │    └── pico/core/runtime.py: _build_prompt_and_metadata()
  │         ├── pico/core/context_orchestrator.py: build()      <-- 动态上下文编排
  │         ├── pico/core/context_pressure.py: compute()        <-- 计算 Context Pressure 压力
  │         └── [若 Context Pressure 超阈值]
  │              └── pico/core/compact.py: compact_history()    <-- 自适应压缩并提炼 compact_summary
  │
  ├── 3. Agent 主循环与完成治理 (v3 ReAct Step Loop & Final Readiness)
  │    └── pico/core/engine.py: AgentEngine.run()
  │         │
  │         ├── Step 1: 模型决策
  │         │    └── pico/providers/clients.py: complete()      <-- 支持文本与 Vision 多模态
  │         │
  │         ├── Step 2: [模型发起 <final>最终回答</final>]
  │         │    └── pico/core/final_readiness.py: check()       <-- [v3 门禁] 校验 Final Readiness
  │         │         ├── 是否已运行必要的编译/测试命令验证？
  │         │         ├── 若未通过就绪检查:
  │         │         │    └── 拒绝退出，注入系统提示："验证尚未通过，请先运行测试"
  │         │         └── 若通过就绪检查:
  │         │              └── 允许返回 Final Answer 并退出循环
  │         │
  │         └── Step 3: [模型发起 Tool 工具调用]
  │              └── pico/core/tool_executor.py: execute()      <-- 按 ToolProfile 校验与防护
  │
  └── 4. 记忆检疫与持久化落盘 (v3 Memory Quarantine)
       ├── pico/features/memory_quarantine.py: inspect()         <-- 将新抽取记忆送入检疫池校验
       ├── pico/features/memory.py: append_daily_log()           <-- 校验通过后方写入 Daily Log
       ├── pico/core/session_store.py: save()                    <-- 持久化 Session
       └── pico/core/run_store.py: write_run_artifacts()        <-- 输出 trace.jsonl 与 report.json
```

## 4. Pico v3 两大硬核新机制

### 4.1 动态上下文编排器 (Context Orchestrator & Pressure)
在 [pico/core/context_orchestrator.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/core/context_orchestrator.py) 中，系统的上下文不再是简单的字符串拼接，而是划分为结构化的 `Sections`（如 System Prefix、Workspace Topology、Memory、History）：
- **压力感知 (Context Pressure)**：系统实时监控上下文占用与可用窗口比例。
- **动态留存 (Retention)**：当压力增大时，按 Section 优先级自动裁剪或替换耗 Token 的历史，维持 Prompt Caching 命中率。

### 4.2 完成治理门禁 (Final Readiness Guard)
在 [pico/core/final_readiness.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/core/final_readiness.py) 中，解决模型“改完代码不测试就急于答复”的通病：
- 当模型输出包含 `<final>` 最终回答时，`FinalReadiness` 会检查当前 Task 的验证状态。
- 如果模型修改了核心文件但尚未运行过测试或构建命令，就绪检查打回 `readiness_passed = False`，强制阻止模型提早退出，要求其先执行验证。
