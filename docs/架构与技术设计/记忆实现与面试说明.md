# Pico v3 记忆系统与面试说明

本文说明 `pico v3` 记忆系统的架构设计哲学、四层记忆模型、Memory Quarantine (记忆检疫池)、Memory Lint 校验机制以及打分召回算法。

---

## 1. 为什么放弃 Vector DB / RAG 选型？

在本地 Coding Agent 场景下，传统 RAG / Vector DB 方案存在三个明显缺陷：

1. **精确代码召回率差**：向量相似度计算在遇到精细代码行、变量名、配置规则时容易失效，反而召回无关代码块干扰模型。
2. **本地开销与依赖过重**：在轻量 CLI 中打包向量数据库（如 Chroma）增加了数十 MB 的依赖包与内存开销。
3. **文件频繁变动维护成本高**：代码与配置被修改后，向量索引重新 Embedding 的延迟与 CPU 消耗极大。

`pico v3` 选择基于**分层 Markdown 文件 + 轻量级标签/词条算分召回 + Memory Quarantine 检疫池**，做到了 **零额外依赖、< 1ms 检索延时、防止坏数据污染，且人类完全明文可读可控**。

## 2. Pico v3 四层记忆架构与检疫流 (Quarantine Flow)

```text
.pico/memory/
├── MEMORY.md                       # 长期记忆大纲索引 (< 200 行，固定进 Prompt)
├── topics/                         # durable memory (4 类主题)
│   ├── user-preferences.md         # 1. 用户角色与协作偏好
│   ├── project-conventions.md      # 2. 仓库约定与命名规范
│   ├── key-decisions.md            # 3. 重大架构决策与理由
│   └── dependency-facts.md         # 4. 关键依赖版本与踩坑记录
├── logs/                           # daily logs (只增不减)
│   └── YYYY/MM/YYYY-MM-DD.md       # 按天追加的原始观察日志
├── quarantine/                     # [v3] memory_quarantine 隔离池 (存放未校验好的候选记忆)
└── .consolidate-lock               # auto-dream 并发互斥锁与时间戳
```

### v3 记忆检疫池 (Memory Quarantine Buffer) 机制：
在 Pico v3 中，从模型对话中抽取的候选记忆不会立即写入长期数据库，而是经过 [memory_quarantine.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/features/memory_quarantine.py) 与 [memory_lint.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/features/memory_lint.py) 校验：
- **Lint 语法与合法性校验**：检测是否有格式畸形、Key-Value 丢失或敏感 Key 泄露。
- **冲突检测与隔离**：如果新提取的记忆与已有的 Durable Topic 存在矛盾事实，放入 `quarantine/` 隔离池暂存，待 Auto-Dream 统一解决冲突后再归档。

## 3. 对接认知心理学 / 经典 Agent 记忆分类

| 经典认知心理学记忆 | Pico v3 架构实现模块 | 存储载体与功能 |
| :--- | :--- | :--- |
| **工作记忆 (Working Memory)** | `session["memory"]` 字段 | 当前任务摘要、最近接触文件短摘要、`file_summaries` |
| **情景记忆 (Episodic Memory)** | Daily Logs 日志 & Session 历史轨迹 | `.pico/memory/logs/*.md` 带时间戳的原始观察日志 |
| **语义记忆 (Semantic Memory)** | Durable Topics 主题文件 | `.pico/memory/topics/*.md` 4 类提炼后的事实与规范 |
| **程序记忆 (Procedural Memory)** | Skills 技能系统 | `.agents/skills/` 结构化 SOP 操作指南 |

## 4. 动态相关记忆召回算法 (`retrieval_candidates`)

在 [pico/features/memory.py](file:///Users/chenfanghang/PycharmProjects/pico/pico/features/memory.py) 中，系统基于三元组 `(exact_tag_match, keyword_overlap, recency)` 降序对记忆进行排序与过滤：

1. **`exact_tag_match` (标签精确匹配)**：`query` 词条命中 Topic/Note 的 `tags`（最高优先级）。
2. **`keyword_overlap` (关键词重叠数)**：`query` 分词与 Note 文本的重叠词数量。
3. **`recency` (时间新鲜度)**：基于时间戳优先选择最新记录。

取 Top-3 匹配条目注入 Prompt：

```markdown
## Relevant Durable Memories (2 candidate matches)
- [project-conventions] 项目并发测试强制使用 pytest-xdist 插件
- [dependency-facts] 项目依赖 Python 3.10+ 环境，使用 uv 管理依赖
```

## 5. 后台 Auto-Dream 梦境炼化流程

在后台守护线程中，`auto-dream` 定期将 Raw Daily Logs 与 Quarantine 隔离池中的数据炼化为 Durable Topics：

1. **门禁与互斥锁**：距上次炼化 `>= 24 小时` 且积累 `>= 5 个 Session`；通过 `.consolidate-lock` 互斥文件锁防止多进程冲突。
2. **沙箱隔离 Worker 子 Agent**：启动独立子 Pico 进程，其工具写权限通过 `write_scope` 被**物理锁定在 `.pico/memory/` 内部**。
3. **检疫冲突解决与归档**：提取 `quarantine/` 中的候选条目，消除事实冲突并整理入 4 类 `topics/*.md`。
4. **裁剪与刷新**：自动更新并重新裁剪 `MEMORY.md` 索引，确保其低于 200 行。
